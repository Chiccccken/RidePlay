# RidePlay 0.3.1 入门

适用于 GitHub 发布页的 RidePlay 公开测试版。先在停车状态下完成设置，再开始骑行。

## 1. 下载与安装

1. 在 [RidePlay 发布页](https://github.com/Chiccccken/RidePlay/releases/tag/v0.3.1)下载 `RidePlay-0.3.1.apk`。同页提供源码与 `SHA256SUMS.txt`；不要把原版 DiPlay 的安装包当成 RidePlay 更新。
2. 安装到 Android 接收设备，最低系统版本为 Android 7.0（API 24）。iPhone 上不安装这个 APK；最低版本能安装不代表每种设备和连接方式都已实测。
3. 打开 RidePlay，按所用功能授予蓝牙／附近设备、Wi-Fi／位置等权限。Siri 和电话相关功能会涉及麦克风权限；通知权限用于连接控制。
4. 只运行一个 CarPlay 接收 App。若设备上还装有 DiPlay 或 RidePlay debug 版，结束它们的连接尝试后再连接当前版本。

基础 CarPlay 连接不以 Root 或 ADB 为前提。部分厂商专用扩展需要额外权限，应按其功能说明单独判断。

## 2. 首次无线连接

1. 打开 Android 系统热点；在 RidePlay 的**设置 → 连接 → 连接设置**中选择使用内置热点，并保存实际热点信息。
2. 核对名称、密码、安全性等信息与系统当前热点一致。App 中保存的描述不会自动修改系统热点。
3. 保持 iPhone 的蓝牙和 Wi-Fi 开启，完成与 Android 接收端的蓝牙配对，在 RidePlay 中选择对应 iPhone 并发起连接。
4. 若失败，先只确认 iPhone 是否已加入接收端热点，再区分入网失败和入网后 CarPlay 启动失败。改动一个条件后重试，并保留诊断报告。

也可使用外部路由器，让 iPhone 和接收端加入同一局域网，然后选择“现有 Wi-Fi／同一局域网”。网络需要允许两台设备互相访问。USB 连接需要支持数据传输的接口和线材；见[完整连接说明](INSTALL.md)。

更换 App 包名时，不要直接删除 iPhone 的 CarPlay 车辆记录：多个接收端可能共用同一条记录，删除可能影响其他设备。

## 3. 按需启用车把媒体控制

如果希望 **Android 显示 CarPlay，音乐由 iPhone 直接通过蓝牙输出到头盔，同时使用 KTM 车把媒体按键**，再配置这一组可选功能。先确认 iPhone 与头盔的日常蓝牙音乐输出正常。

入口：**设置 → 高级 → 视频与音频**。

| 选项 | 用法 |
| --- | --- |
| 通过车辆蓝牙播放 CarPlay 音频（实验性） | 上游的音频直连选项；无音频媒体控制需要开启它。 |
| 无音频媒体控制（实验性） | 不接收本地音乐时，仍发布 Android 媒体会话，转发播放／暂停／上一首／下一首。 |
| 媒体按键选路引导（实验性） | 默认关闭。仅在需要帮助系统选择 RidePlay 接收媒体按键时启用；可能接管其他 Android 播放器的媒体按键控制权。 |
| 无音频控制申请焦点（实验性） | 是独立实验，可能暂停或压低其他 Android 应用的声音，不是上面两个开关的必选依赖。 |

选路引导会短暂播放无声数据来尝试取得媒体按键控制权。请阅读每项开关的说明：有些改动立即重连，有些在下次连接生效。完成配置后再验证车把操作与 iPhone 到头盔的音乐输出；Android 媒体卡片可用不能代替实车验证。

## 4. 按需启用歌曲信息拼音

在同一张“视频与音频”卡片中，Android 10 及以上可开启**歌曲信息拼音（实验性）**，再选择专辑名拼音或歌手名称替换。默认关闭，改动在下次连接生效。

拼音在设备本地转换，只影响 Android 媒体会话，CarPlay 画面保留原文。系统媒体卡片也会看到转换后的文字；人名和多音字可能需要自行添加完整名称替换。详见[拼音说明](RIDEPLAY_PINYIN.md)。

## 5. 更新、备份与迁移

- 在**关于 RidePlay**中检查更新，或从本仓库发布页下载。同一正式包名、相同签名的更新可覆盖安装并保留数据；安装会结束当前 CarPlay 会话，之后重新连接。
- 正式版是 `com.chiccccken.rideplay`，debug 版是 `com.chiccccken.rideplay.debug`，两者数据独立。
- 迁移前进入**关于 RidePlay → 备份设置 → 在手机上备份或恢复**，按提示在同一网络的手机浏览器导出设置。导入会应用备份中的偏好，先保留当前备份，再核对文件来源与内容。
- 设置备份包含 RidePlay 的媒体控制、拼音、歌手名称和方向偏好，不迁移 iPhone 配对密钥或热点名称／密码。新安装仍需自行设置权限、选择 iPhone 并保存实际热点信息。

## 6. 出问题时保留什么

在**设置 → 诊断 → 保存诊断报告**导出当前版本的报告，通常位于 `Downloads/DiPlay`；若系统无法写入该目录，按导出后的提示查看实际位置。

记录 App 版本、Android 与 iOS 版本、接收设备／车型、连接方式、复现步骤和大约失败时间。先保存证据，再考虑修改配对或网络配置。联系维护者时附上经过检查的报告，避免把尚未在原版复现的 RidePlay 定制问题直接当作上游缺陷提交。

报告会过滤常见标识和敏感内容，但公开前仍需自己检查。不要公开上传热点密码、配对材料、签名密钥或完整系统错误报告。报告不会自动上传；详见[隐私说明](PRIVACY.md)。

## 当前验证边界

0.3.1 已获得安装连接、App 内重连、接收设备重启后打开 App 再连接、多次实车车把控制，以及 iPhone 到头盔音乐输出的使用反馈。首个实测车型是 2019 KTM 390 Duke。

其他车型、Android 系统、Siri／电话音频、完整后台／锁屏恢复和启动方向仍需单独验证。以[当前发布说明](RELEASE-NOTES-0.3.1.md)为准，早期试验文档保留当时记录。
